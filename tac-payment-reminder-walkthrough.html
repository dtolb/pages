Running on Gemini — two paths

PathAgent lives inIntegration
Gemini as the model Your code. Prompt and the three TAC tools unchanged. Gemini's OpenAI-compatible endpoint. Swap model= only.
CX Agent Studio Google. Prompt, flows and tools configured in the platform. Handler forwards the utterance to the Sessions API (runSession / streamRunSession) and speaks the reply. Twilio is a listed deployment target.

On the CX Agent Studio path, to_openai_agents_sdk_tool() and the three tools drop out — tool execution is platform-hosted. Steps A, B, E and F of the chart above are unchanged; C and D move to Google.

The three tools

Tools are defined as TAC objects and converted to the model runtime's format at the last moment, so the runtime is swappable.

ToolBuilt withDoes
search_renewal_faq SDK built-in Queries Enterprise Knowledge, so answers come from approved content.
send_payment_link Your own function Sends the SMS. Schema comes from the signature and docstring.
connect_to_human_agent SDK built-in Ends the AI session and releases the live call.

Design rules

Four constraints that shape the agent.

RuleDetail
The model never sees the phone number The destination is an injected argument, hidden from the model and supplied from the session. The model decides whether to text, never whom.
Bind tools per conversation Injection mutates the tool in place, so one shared instance leaks a caller's session into another caller's turn. Build per turn.
Voice and SMS get different agents Voice gets all three tools; an SMS reply gets knowledge only, and its own prompt — replies arrive with empty history and must not re-introduce the agent.
Consent is explicit Agreeing to “is now a good time?” is not agreeing to receive a text. The prompt states this, or the agent texts on the first “yes”.

One call, two far ends

The call never drops. Only who is on the other end changes.

When the relay session ends the call is still up, and Twilio asks the app what to do next. The app answers with <Dial><Client> and the browser rings. Twilio asks on every relay ending, not just deliberate handoffs, so the app only dials when handoff data is present.
