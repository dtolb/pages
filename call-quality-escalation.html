The client detects, the server decides, and Twilio persists only while the flag is on. Twilio's row is empty under “on trip” because enabling ACI has no effect on the call that triggered it.

ACI is forward-only
Eligibility is fixed when a call is created, with no backfill. Enabling ACI during a call returns no data for that call, including its remaining minutes. Querying an ineligible call returns HTTP 401 / error 17007. The call that triggers escalation is never instrumented.
Account-scoped toggle
No per-call, per-number, or per-TwiML-app scoping exists. The per-tenant subaccount is the only isolation boundary available.
Voice Trace is not readable
It saves RTP for Twilio Support. No API, no Console download, 10-day retention, and captures cannot be shared outside Twilio. Its use here is evidence for a carrier ticket.
What the flag controls
Twilio computes the metric stream in-flight on every call and discards it when the flag is off. The SDK already posts samples to eventgw.twilio.com in 10 s batches at no charge. Reading the same data in the browser gives 1 Hz resolution and does not depend on the flag.

03

Client-side detection

Derive state from sample. Warning state is unsuitable as the direct driver: warnings are suppressed for the first 5000 ms of a call, and clearing requires 0-of-10 clean samples plus a 5 s hold, so recovery lags by at least 10 s. Warnings are still recorded, since they match the sdk_edge events ACI returns.

SignalStateConditionAgent message
Goodp50 MOS ≥ 4.0 over last 10 snone

Badp50 MOS < 3.1, or low-bytes-*, or far-end silenceState the direction

ice-connectivity-lost, low-bytes-* and reconnecting set the worst state immediately rather than waiting for MOS to decay. Do not reuse PreflightTest.CallQuality bands: they are non-contiguous in source, so MOS 4.05 matches no branch and reports degraded.

300 is ~0.9 % of the 0–32767 range, matching the SDK's own minStandardDeviation: 327.67. Unsuitable alternatives: constant-audio-input-level (suppressed while muted, ~10 s to fire, measures the local microphone), constant-audio-output-level (excluded from the app-facing emit by an explicit guard), and the volume event (local measurement; inputVolume stays active when the send path is dead).

Pre-shift preflight

Device.runPreflight(token, options) is static, free, and requires no ACI. Run it at agent login to identify networks that will not support a call, before any customer is routed. It is the only free source for isTurnRequired; the in-call sentinel cannot determine that without injecting a custom RTCPeerConnection.

Report fieldUse
isTurnRequiredUDP is blocked. True when a selected candidate has candidateType === 'relay', so media is relayed through TURN. Agent network topology rarely changes mid-shift, so once per login is sufficient.
callQualityVerdict from average MOS. Absent if no sample had mos > 0.
stats.{jitter,mos,rtt}{average, min, max}. Absent under the same condition.
warnings[]{name, description, rtcWarning?}.
networkTimingKeys are signaling, peerConnection, ice, dtls. Each {start, end?, duration?}.
selectedIceCandidatePairStats, iceCandidateStats[]Selected pair and full candidate list.

Requires a valid access token and a record-and-play TwiML application, or <Echo/> with fakeMicInput: true, in which case the test self-terminates after 20 s. Option defaults: codecPreferences: ['pcmu','opus'], edge: 'roaming', signalingTimeoutMs: 10000. Events are completed(report), connected(), failed(err), sample(), warning(); completed and failed are mutually exclusive, and stop() raises failed with 31008 rather than completed. warning emits a single object, not (name, data) as the typings claim. Documentation examples showing iceConnection, preflightTest, startTime or warningsCleared are from the mobile preflight schema.

04

Trip conditions and enabling ACI

Basic Trip on a single call

The sentinel beacons degraded on any of: p50 MOS < 3.1 sustained ≥ 15 s; low-bytes-sent or low-bytes-received; far-end silence ≥ 10 s; reconnecting; or two or more concurrent high-* warnings. On a trip, enable ACI for the tenant subaccount. Add VoiceTrace only when a carrier fault is suspected and a ticket is intended. 

# GET first. POST is a partial update: sending only
# AdvancedFeatures=false leaves VoiceTrace unchanged.
curl -G https://insights.twilio.com/v1/Voice/Settings \
  --data-urlencode "SubaccountSid=AC..." \
  -u "$TWILIO_API_KEY:$TWILIO_API_SECRET"

curl -X POST https://insights.twilio.com/v1/Voice/Settings \
  --data-urlencode "SubaccountSid=AC..." \
  --data-urlencode "AdvancedFeatures=true" \
  --data-urlencode "VoiceTrace=true" \
  -u "$TWILIO_API_KEY:$TWILIO_API_SECRET"

Diagnosis with ACI enabled

The two legs are separate Call SIDs with non-overlapping edge sets, correlated by ConferenceSid. The client leg carries sdk_edge and client_edge; the PSTN leg carries carrier_edge only. There is no client-side MOS for a PSTN caller.

Tag thresholds differ by edge. On sdk_edge, high_latency is RTT > 400 ms and low_mos is < 3.5. On gateway edges, high_latency is internal RTP traversal > 150 ms. Do not aggregate them. Omitting the Edge parameter on /Metrics and /Events returns only the default edge for the call type.

Agent-side checks

  • Ethernet vs Wi-Fi; 2.4 vs 5 GHz; channel congestion
  • VPN or SD-WAN: split-tunnel media
  • Proxy such as Zscaler: media bypass
  • UDP 10000–20000 egress to Twilio media IPs
  • DSCP honoured downstream (dscp:true is the SDK default)
  • Bandwidth contention, CPU load, competing tabs
  • codecPreferences defaults to ['pcmu','opus']. Opus is more loss-tolerant

Disabling ACI

  1. Export metrics, events and summaries to local storage. Availability after clearing the flag is undocumented.
  2. Wait for the ingestion tail, up to 30 min after the last instrumented call ends.
  3. GET, then POST both flags false explicitly.
  4. Voice Trace separately, once Support has the Call SIDs. Raw RTP, 10-day retention, documented consent and HIPAA caveats. <Pay> and PCI-redacted calls are never captured.
06

Correlation before escalating

Advanced Optional refinement to section 04

Most quality complaints are agent-local. For those, the sentinel already holds the answer, so ACI adds cost without adding information. Correlating a tenant's concurrent calls before escalating avoids that, and correlation itself is free.

Observation across the tenant's concurrent callsScopeAction
1 agent degraded, ≥ 3 peers cleanAgent-localDo not escalate
≥ 2 agents sharing an egress IPSite networkEscalate
≥ 30 % of active calls, across ≥ 2 sitesTenant-wide or carrierEscalate + trace
Agents clean, but 32014 or far-end silence on ≥ 2 callsPSTN sideEscalate + trace
  • Site is derived at ingest from the observed source IP of the beacon request. A browser cannot reliably determine its own public egress address, and a self-reported value would be incorrect behind NAT, VPN, or a proxy. Fully remote tenants show one site per agent, reducing the site rule to the agent-local rule.
  • Correlation requires at least 3 concurrent calls. Tenants below that cannot be disambiguated. Fall back to escalating after 2 consecutive degraded calls, with attribution unknown until ACI data arrives.
07

Later considerations

Deliberately excluded from the initial scope.

  • Budget-bounded windows

    ACI bills per minute across the whole subaccount, so a fixed wall-clock window costs a different amount per tenant depending on concurrency: 40 concurrent calls consume the same minutes in 25 min that 5 concurrent calls consume in 200. Expressing the window in billable minutes gives every tenant the same ceiling. Indicative: 1,000 billable min ≈ $2.40 per incident; 10,000 ≈ $24 per tenant per month as a hard stop. Requires per-tenant usage tracking.

  • Repeat-offender reporting

    A short window will miss faults that recur on a longer cycle. Rather than enabling ACI permanently, count trips per tenant and report any tenant tripping 3 or more times in 7 days for manual review.

  • Threshold calibration

    The MOS bands and trip conditions here are starting values. Distributions vary by codec, geography and headset. Collect client-side history before fixing them.

08

Gotchas

  • 32014 is WARNING level, not ERROR. So are 32011, 32009, and conference-callback failure 16011. A LogLevel=error filter on Monitor Alerts excludes them.
  • Event Streams mirrors configured callbacks. com.twilio.voice.status-callback.* fires only if statusCallback and statusCallbackEvent are already set on the call.
  • com.twilio.voice.webhook.status-callback.* is deprecated. Use the form without webhook..
  • The conference statusCallback URL is set by the first participant to join and cannot be overridden by later participants.
  • Monitor Alerts list and instance responses differ. request_variables, response_body and headers are returned only on the instance resource, requiring list-then-fetch per SID.
  • ice-connectivity-lost emits with no second argument. call.on('warning',(n,d)=>d.threshold) throws.
  • Thresholds are not configurable in v2.x. StatsMonitor.Options.thresholds is private, and the injection hook is typed new () => StatsMonitor, which cannot carry configuration.
  • low-mos fires at MOS < 3 in the JS SDK; Insights tags low_mos at < 3.5. Choose one threshold or client and ACI data will disagree.
  • Conference recordings are single-channel. Per-leg dual-channel analysis requires separate <Start><Recording> per leg.
  • Retention: Voice Insights 30 days, Voice Trace 10 days, Event Streams application logs 7 days.
